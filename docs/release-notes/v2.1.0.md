# Clippy Vision v2.1.0 Release Notes

## Overview

This release builds on Clippy Vision v2.0.0 with experimental Linux support, in-app chat, expanded private-window detection, OS capture opt-outs, MCP safety labeling, and unsigned Windows/Linux packaging.

**Version:** `v2.1.0`

**Baseline:** Clippy Vision v2.0.0 ([commit 8271941](https://github.com/protocorn/clippy-vision/commit/8271941), October 9, 2026)

**Included Platforms:** Windows NSIS installer and Linux AppImage (unsigned). macOS installers are excluded (opt-in workflow only).

Verification labels:
- **CI-only** — unit/integration tests in GitHub Actions
- **Xvfb launch** — packaged Linux AppImage under Xvfb in `.github/workflows/release.yml`
- **Windows silent install** — packaged NSIS installer on `windows-latest` in that workflow
- **real machine** — a physical desktop; v2.1.0 has not been tested on one

This release was **CI-tested only**. There has been **no real-machine testing** for v2.1.0. The Windows installer and Linux AppImage are **unsigned**.

## What the release dry-run proves (and does not)

The PR dry-run of `.github/workflows/release.yml` is the maintainer go/no-go bar for packaging:

**Intended to prove:** the packaged Windows installer and Linux AppImage start, and — after first-run setup is already complete — the Electron main process spawns the Python backend and `GET /health` returns HTTP 200.

**Does not prove:** the interactive setup wizard, Ollama, a real chat/embedding model, or real hardware/desktops (GNOME, KDE, Win32 UI Automation on a personal PC, etc.).

**CI bypasses used to reach `/health` (not shipped to users):**
- `setup_complete.json` is pre-seeded at Electron `userData` (the `SETUP_FLAG` path in `electron-ui/electron/lib/paths.js`: `<userData>/setup_complete.json`, not `<userData>/data/`). That skips the wizard so `main.js` runs preflight and `api.startServer()`.
- `llm_config.json` in `<userData>/data/` sets `base_url` to `http://127.0.0.1:11555` so `usesManagedOllama()` is false.
- `scripts/ci_llm_stub.py` answers `GET /` and `GET /api/tags` for the seeded `chat_model` (`test-model`).
- Python 3.12 plus `requirements.txt` are installed on the runner; `CLIPPY_PYTHON` points the packaged app at that interpreter. Python is not inside the installer or AppImage.

## New Features

### 1. Experimental Linux support ([#10](https://github.com/protocorn/clippy-vision/pull/10), [#14](https://github.com/protocorn/clippy-vision/pull/14), [#20](https://github.com/protocorn/clippy-vision/pull/20), [#26](https://github.com/protocorn/clippy-vision/pull/26))

**Verification:** **CI-only** for capture/AT-SPI/setup-check tests. Packaged AppImage **Xvfb launch** in [run 38286025883](https://github.com/protocorn/clippy-vision/actions/runs/38286025883): `/health` 200 `{"status":"ok"}`. **Not real machine.**

What the Linux code path implements:
- Window metadata (`xdotool`), process names (`psutil`), clipboard (`wl-paste` / `xclip` / `xsel`), idle (`xprintidle` / `xdotool`)
- X11 screenshots via `mss` with focused-window crop and a blank-frame guard
- Wayland session detection: compositor is logged, capture is skipped (no blank JPEGs stored)
- AT-SPI accessibility text ([#20](https://github.com/protocorn/clippy-vision/pull/20)) — **CI-only**; not tried on a real desktop
- Setup wizard OS check accepts Linux ([#26](https://github.com/protocorn/clippy-vision/pull/26)) — **CI-only**; the wizard itself is not driven in the dry-run

Known Linux gaps:
- No native Wayland screenshot capture (xdg-desktop-portal not implemented)
- No browser URL or private-window detection on Linux
- AppImage is unsigned

**Installation (Linux):**

1. Install a system **Python 3.11+** (see Python runtime below). Python is not in the AppImage.
2. Download `ClippyVision-Linux-x86_64-2.1.0.AppImage`
3. `chmod +x ClippyVision-Linux-x86_64-2.1.0.AppImage`
4. Optional capture helpers: `xdotool`, `x11-utils`, `xprintidle`, `xclip`/`xsel`/`wl-clipboard`
5. Run the AppImage. Complete the setup wizard on first launch (the dry-run does not exercise that wizard).

### 6. OS-level window capture opt-outs ([#28](https://github.com/protocorn/clippy-vision/pull/28))

**Verification:** **CI-only** (mocked APIs). **Not real machine.**

When the foreground window asks not to be captured, Clippy skips screenshot, OCR, accessibility text, and clipboard content and records at most a minimal redacted event.
- Windows: `GetWindowDisplayAffinity` (`WDA_EXCLUDEFROMCAPTURE` / `WDA_MONITOR`)
- macOS: frontmost layer-0 window sharing state
- Linux: no standard per-window API; process-name fallback only (password-manager executable names)

Detection errors fail open (allow capture). Browser private-window detection ([#8](https://github.com/protocorn/clippy-vision/pull/8)) is separate.

## Python runtime (not bundled)

**A system Python 3.11 or later is required. Python is not bundled** in the Windows installer or the Linux AppImage.

`requirements.txt` does **not** pin a Python version. The packaged app does not contain an interpreter.

Resolution (`electron-ui/electron/lib/paths.js`): `CLIPPY_PYTHON` if set, else `python3` (non-Windows) or `python` (Windows) from PATH.

CI unit tests and the release dry-run use **Python 3.12** (`.github/workflows/tests.yml`).

**When Python is missing, the setup wizard (`electron-ui/electron/lib/setup.js`) does this:**
- It parses `python --version` and requires **Python 3.11+**. Preflight text is "Clippy needs Python 3.11+ on PATH." / "Checking for Python 3.11+". Python 3.9 and 3.10 are rejected.
- **Windows:** `winget install Python.Python.3.11 --silent`. If winget fails: "Could not install Python. Please install manually from python.org". If install succeeds but PATH does not: "Python installed but not on PATH. Restart required."
- **macOS and Linux:** tries Homebrew `brew install python` when `brew --prefix` works. If that does not yield a working interpreter: log "Install Python 3.11+ from python.org or Homebrew, then retry." and step error "Install Python 3.11+ and make sure it is on PATH." Linux is **not** installed via apt by the wizard.

To force an interpreter (PowerShell):

```powershell
$env:CLIPPY_PYTHON = "C:\path\to\python.exe"
```

Linux/macOS:

```bash
export CLIPPY_PYTHON=/path/to/venv/bin/python3
```

## Known issues

### Private-browsing docs overstate coverage ([#16](https://github.com/protocorn/clippy-vision/issues/16))

v2.1.0 ships without waiting for [issue 16](https://github.com/protocorn/clippy-vision/issues/16). Several docs claim more private-browsing protection than the code was tested for, and they contradict each other:

- `docs/usage.md` says Firefox, Opera, and Vivaldi private windows "are covered on Windows", then two lines later says "Firefox, Opera, and Safari are not covered." The first sentence treats [#8](https://github.com/protocorn/clippy-vision/pull/8) as finished product coverage. Those extra detectors are **CI-only** (mocked accessibility trees). Nobody opened a real Firefox, Opera, or Vivaldi private window.
- `PROJECT_VISION.md` says Chrome, Edge, Brave, Firefox, Opera, and Vivaldi private windows "are blacked out on Windows" as if that were verified. Firefox/Opera/Vivaldi on Windows have no **real machine** test.
- `core/private_windows.py` still documents only Chrome, Edge, or Brave.
- What the code actually does: Windows tries Chrome, Edge, Brave, Opera, Vivaldi, and Firefox; macOS AppleScript is attempted for Chrome, Edge, Brave, Firefox, and Opera (Firefox/Opera **untested** on a Mac; Vivaldi is not in the macOS map); Safari is not covered; Linux always returns false.
- Pause capture when a private window must not be stored.

### Python 3.11+ is not bundled

Install a system **Python 3.11+** before first run. The NSIS installer and AppImage do not ship an interpreter. Set `CLIPPY_PYTHON` to pick one; otherwise the app uses `python` (Windows) or `python3` (Linux/macOS) from PATH. See Python runtime (not bundled) above.

### Unsigned installers

All installers are unsigned.
- **Windows:** SmartScreen will warn ("Windows protected your PC"). Choose **More info → Run anyway**.
- **Linux AppImage:** run `chmod +x ClippyVision-Linux-x86_64-2.1.0.AppImage` before the first launch.
- **macOS** (not in this release): Gatekeeper block; right-click → Open, or `xattr -d com.apple.quarantine`.

Verification labels for every feature above are **CI-only**, **Xvfb launch**, **Windows silent install**, or **real machine**. There has been no **real machine** testing for v2.1.0.
